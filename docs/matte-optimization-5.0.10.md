# v5.0.10：常规遮罩不再逐帧创建全画布 Bitmap

## 修改范围

`SVGACanvasDrawer` 的常规遮罩使用 `saveLayer + DST_IN` 合成，由 Canvas 管理
临时图层的生命周期。硬件 Canvas 上，遮罩图片通过 BitmapShader 绘制其 alpha；
普通内容图片继续使用原来的绘制方式。DST_IN Paint 在 drawer 内复用。

该路径不再调用 Bitmap.createBitmap 创建全画布 ALPHA_8 遮罩，也不保留跨帧
可变遮罩缓冲。每个遮罩组有独立图层，避免延迟执行时读到别组或别帧的内容。
尺寸变化直接交给当前 Canvas；异常仍由 v5.0.9 的 finally 清理图层和 sprite。

自定义 `dynamicDrawer` / `dynamicDrawerSized` 遮罩回调保留原来的软件 Canvas
路径，仍会创建 ALPHA_8 Bitmap。这些回调可能依赖软件绘制行为，不能直接换
Canvas 类型。当前优化针对普通素材中的图片、文字及形状遮罩。

## 方案验证

曾验证过按分组复用 ALPHA_8 Bitmap：常规逐帧输出相同，但在先记录多帧、
稍后执行 GPU 绘制时，透明帧读到后续帧的数据，确认存在串图，因此没有采用。

直接将遮罩 Bitmap 画到 GPU 图层也产生半透明差异。最终仅在硬件遮罩图片
路径使用 BitmapShader；常规内容图片不改，以保留原有透明度表现。

## 实机回归

设备：vivo V2425A / Android 16。独立 app_process，不安装或重启 Ark。

- 单遮罩、双遮罩、同遮罩多组、透明帧、半透明叠加、无遮罩素材。
- 64×64、96×96、48×48 画布与尺寸切换。
- 记录三帧后再按顺序执行 GPU 绘制，验证内容不会跨帧覆盖。
- 父 Canvas 平移、缩放、裁剪与素材自身的 clipPath。
- 自定义遮罩回调仍收到软件 Canvas，调用次数和画面正确。
- v5.0.9 的图层异常清理、Glide 图片所有权回归继续通过。

176 项绘制断言 + 10 项生命周期断言，失败 0 项。

对 45 组 GPU 画面逐像素比较，25 组 SHA-256 完全相同，其余差异位于缩放
边缘。半透明颜色按预乘值比较；差异属于少量抗锯齿/采样舍入，不声称全部
像素完全相同。软件 Canvas 原版遮罩存在的透明区合成失败用例在新实现下通过。

测试读取 ImageReader 的预乘 RGBA 后进行颜色还原；半透明内容的参考 alpha
从独立的未加遮罩 Bitmap 绘制中获取，避免把设备 Bitmap 绘制行为误算为
遮罩合成误差。

## 独立合成场景耗时

720×720，双遮罩，预热 15 帧后采样 60 帧，单位 ms：

| 项目 | v5.0.9 | v5.0.10 候选 |
|---|---:|---:|
| 录制 p50 | 10.98 | 0.36 |
| 录制 p95 | 18.34 | 1.20 |
| 录制至 GPU 提交完成 p50 | 17.71 | 3.09 |
| 录制至 GPU 提交完成 p95 | 24.70 | 8.05 |

这是单设备合成用例，不是完整直播间帧率，也不是总 PSS 下降数据。
临时 GPU 图层仍占图形内存；消除 CPU Bitmap 分配不等于绘制不再需要内存。
没有测出这项修改能把当前约 700MB 总内存降低到多少。
